What this doesn't fix

Every spawned peer still lands in one flat, machine-global name list. Filtering solves what the hierarchy's own files show a team — it can't rename a process. That's why each team's prefix must differ:

myrepo-architect alpha-architect
myrepo-architect beta-architect
The first team gets asked too

The prefix a team gets isn't just a collision fallback — it's every name that will ever show up in ListAgents for that team, so the very first create in a fresh repo asks, the same way a second team's does.

accept → myrepo-*
override → alias --set <name>, then create

Accepting changes nothing — it's the prefix create would have used anyway. Overriding is exactly what alias --set already does today, just offered up front instead of discovered later.

Default team, no --team flag: behaves exactly as it does today once named — this whole two-team picture only appears once a second team exists.
